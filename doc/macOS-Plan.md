# Native macOS Client Plan

Plan for building a native macOS version of Riff with feature parity to the GTK app. Both clients live in this repository (the `Aidenir/riff` fork) and both stay buildable.

## Decisions

| Topic | Decision |
| --- | --- |
| Repository | Fork only. Not intended for upstream (upstream does not accept AI-generated contributions). |
| Parity target | Frozen at 26.10 (`d4d377f`). No further upstream merges are tracked. |
| UI stack | SwiftUI, with AppKit where SwiftUI falls short, on top of the Rust core via UniFFI. |
| Parity meaning | Every page, action and setting of the GTK app, expressed with Mac idioms (sidebar, toolbar, menu bar, Settings window). Not a pixel copy of libadwaita. |
| Shared Rust | The data layer, auth, play queue, audio engine and librespot player are shared. App state stays per client (see changes below). |
| Platform seam | Default-on cargo features (`gtk`, `gsettings`, `secret-service`) plus a `PlayerDelegate` trait. Linux builds with the defaults; the Mac core turns them off. |
| Linux | Behaviour unchanged. Meson build and existing workflows must stay green after every slice. |
| Minimum OS | macOS 26. |
| Architecture | Apple Silicon (arm64) only. |
| Project layout | `macos/` SwiftPM package, built into an app bundle by `scripts/build-macos.sh`. |
| Spotify API crate | Generated by `scripts/generate-spotify-api.sh` (Java) as on Linux. |
| Bundle id | `com.aidenir.Riff`, app name "Riff". |
| Signing | Ad-hoc signed, hardened runtime on, App Sandbox off. Developer ID signing and notarization are added once an Apple Developer account exists. |
| Distribution | DMG attached to GitHub releases. No Mac App Store. |
| CI | New GitHub Actions workflow `riff-macos.yml` on a `macos-26` runner. Existing Linux workflows untouched. |
| Translations | `po/*.po` converted to `Localizable.strings` per language by `scripts/po-to-strings.py`. |
| Dev tools | Same feature flags as Linux. A Debug menu in the menu bar, Debug configuration only. |
| Ownership | Agents write both Rust and Swift. Rust changes are kept mechanical (moves, trait extraction) so they are reviewable without deep Rust knowledge. |
| Verification | Parity checklist ticked per slice, Rust tests for shared logic, Swift unit tests, Linux build checked in a Fedora container, manual run with screenshots. |

## Changes from the first draft

Found while building, decided without stopping:

- **App state is not shared.** `src/app/state` holds GObject list models (`SongListModel`, `ListStore<CardModel>`) that GTK widgets bind to, so it is not UI-free. Sharing it meant rewriting the GTK pages too. Instead the Mac core (`crates/riff-ffi`) has its own playback controller on top of the shared `PlayQueue`, and the Swift views keep page state. Confirmed with Viktor.
- **SwiftPM instead of XcodeGen.** The build machine has only the Command Line Tools, which cannot run `xcodebuild`. SwiftPM builds the app with either the Command Line Tools or Xcode, and the script assembles and signs the bundle. Nothing to generate or ignore.
- **`.strings` instead of a String Catalog.** Compiling `.xcstrings` needs Xcode. `.strings` files work everywhere and SwiftUI looks them up the same way.
- **Settings in a JSON file instead of `UserDefaults`.** The player reads settings from Rust threads, so the core owns them (`~/Library/Application Support/com.aidenir.Riff/settings.json`, same keys and defaults as the GSettings schema). Card size is a pure view preference and uses `@AppStorage`.

### Rust work

1. **Shared crates build without GTK.** Each GTK-only dependency is behind a default-on feature:

    | Concern | Linux (default features) | macOS (features off) |
    | --- | --- | --- |
    | Images | `gdk-pixbuf` decode into a `gdk::Texture` (`riff-api`, `gtk`) | `LoadedImage` is the encoded bytes; Swift decodes them |
    | Default labels | gettext (`riff-api`, `gtk`) | English source strings |
    | Settings | GSettings (`riff-config`, `gsettings`) | JSON store in `riff-ffi` |
    | Credentials | `oo7` Secret Service (`riff-auth`, `secret-service`) | Keychain via `security-framework` |
    | Audio output | librespot alsa / pulseaudio | librespot `rodio` (CoreAudio), `AudioBackend::System` |
    | Cache directory | `glib::user_cache_dir()` | `~/Library/Caches` |
    | Media keys | MPRIS over D-Bus (`src/dbus`) | `MPNowPlayingInfoCenter`, `MPRemoteCommandCenter` |
    | Suspend inhibit | logind (`src/inhibitor.rs`) | `IOPMAssertionCreateWithName` |

2. **`crates/riff-player`.** The librespot player moved out of `src/player` unchanged except for a `PlayerDelegate` trait, which replaces the direct `AppAction` sends and GSettings reads. `src/player/mod.rs` implements it for GTK.
3. **`crates/riff-ffi`.** `staticlib` with UniFFI bindings. `RiffCore` wires up token stores, the api service and the player like `App::new`. It exposes async catalog and library calls, playback commands, settings, Spotify Connect, and a `Listener` for events. `playback.rs` mirrors the GTK `PlaybackState` reducer on the shared `PlayQueue`, including paged contexts, skip-explicit and Connect routing.

### Build

- `./scripts/build-macos.sh [debug|release] [--dmg] [--run]`:
  1. Run `scripts/generate-spotify-api.sh` if `generated/spotify-api` is missing.
  2. `cargo build -p riff-ffi`.
  3. Generate Swift bindings with the crate's `uniffi-bindgen` (`--metadata-no-deps`, so cargo does not fetch every platform's crates).
  4. Convert `po/*.po` with `scripts/po-to-strings.py`, render the icon with `scripts/make-macos-icon.sh`.
  5. `swift build`, assemble `build/macos/Riff.app`, ad-hoc sign with the hardened runtime.
  6. `--dmg` packs `build/macos/Riff-<version>.dmg`.
- `./scripts/test-macos.sh` runs the GTK-free Rust tests and the Swift tests.
- Host requirements: macOS 26 with Xcode or the Command Line Tools (Swift 6.2), Rust, Java.
- Linux: `meson`, `scripts/build.sh` and Flatpak are unchanged.

### CI

`riff-macos.yml` on `macos-26`: generate the API crate, `build-macos.sh release --dmg`, `test-macos.sh`, upload the DMG, and attach it to the release on `v*` tags. Notarization (`notarytool`) is a separate step to add once a Developer ID exists.

## Slices

Each slice ends with the Linux build green, the Mac app building, and the parity checklist rows for that slice ticked.

1. **Rust extraction.** Done. Features gate GTK in the shared crates, `riff-player` extracted, `riff-ffi` added.
2. **Login and playback.** Done. Browser OAuth, Keychain session restore, playback bar, Now Playing and media keys, sleep prevention.
3. **Library.** Done. Sidebar with playlist folders, saved albums, playlists, liked songs, followed artists, artwork cache, track table with multi-select, like, follow.
4. **Search and details.** Done. Search with scopes, album, artist, playlist and user pages, playlist create/edit/cover, add and remove tracks, recommendations, Spotify links and clipboard detection.
5. **Queue, lyrics, home.** Done. Queue page and side panel with reordering, synced lyrics, home shelves, now playing page.
6. **Settings, audio engine, Connect.** Done. Settings window, equalizer, pan, pitch, normalisation, caches, Connect device menu, Debug menu, shortcuts.
7. **Release.** Done. App icon, translations, DMG packaging, CI workflow, README section.

## Risks

- **Not run while logged in.** The app builds, launches and shows the login screen, but logging in needs a Spotify Premium account in a browser, so nothing behind login has been run yet. Playback through rodio, the track tables, Connect and the home shelves need a manual pass.
- **librespot on macOS.** The `rodio` backend has not been exercised in this codebase on macOS before. The local player itself compiles and starts.
- **Linux runtime.** The Linux build and tests pass in a Fedora 44 container, but the GTK app was not run with a display after `src/player` moved to `riff-player`. The move did not change logic.
- **PlayPlay DRM.** Some accounts fail on Linux for this reason. The same applies on macOS and is out of scope.
- **Unsigned distribution.** Until notarization exists, users must clear the quarantine attribute or use right-click Open.
