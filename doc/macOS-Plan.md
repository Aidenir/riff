# Native macOS Client Plan

Plan for building a native macOS version of Riff with feature parity to the GTK app. Both clients live in this repository (the `Aidenir/riff` fork) and both stay buildable.

## Decisions

| Topic | Decision |
| --- | --- |
| Repository | Fork only. Not intended for upstream (upstream does not accept AI-generated contributions). |
| Parity target | Frozen at 26.10 (`d4d377f`). No further upstream merges are tracked. |
| UI stack | SwiftUI, with AppKit where SwiftUI falls short, on top of the Rust core via UniFFI. |
| Parity meaning | Every page, action and setting of the GTK app, expressed with Mac idioms (sidebar, toolbar, menu bar, Settings window). Not a pixel copy of libadwaita. |
| Shared Rust | `src/app/state`, `src/player` and `src/connect` are extracted into a UI-free crate used by both clients. |
| Platform seam | Small Rust traits with a GTK implementation and a macOS implementation, selected at compile time. |
| Linux | Behaviour unchanged. Meson build and existing workflows must stay green after every slice. |
| Minimum OS | macOS 26. |
| Architecture | Apple Silicon (arm64) only. |
| Project layout | `macos/` directory with an XcodeGen `project.yml`. The `.xcodeproj` is generated and gitignored. |
| Spotify API crate | Generated by `scripts/generate-spotify-api.sh` (Java) as on Linux. |
| Bundle id | `com.aidenir.Riff`, app name "Riff". |
| Signing | Ad-hoc signed, hardened runtime on, App Sandbox off. Developer ID signing and notarization are added once an Apple Developer account exists. |
| Distribution | DMG attached to GitHub releases. No Mac App Store. |
| CI | New GitHub Actions workflow on a `macos-26` runner. Existing Linux workflows untouched. |
| Translations | `po/*.po` converted to a String Catalog (`Localizable.xcstrings`) by a build script. |
| Dev tools | Same feature flags as Linux. A Debug menu in the menu bar, Debug configuration only. |
| Ownership | Agents write both Rust and Swift. Rust changes are kept mechanical (moves, trait extraction) so they are reviewable without deep Rust knowledge. |
| Verification | Parity checklist ticked per slice, Rust tests for shared logic, Swift unit tests for view models, manual run with screenshots. |

                 |  GTK app (src/)           |      |  Mac app (macos/)         |

                 |  player (librespot), Spotify Connect, plain data models      |
                 +-------------+------------------------------------------------+
                               |

       +-----------+-----------+-----------+-------------+------------------+

### Rust work

1. **New crate `crates/riff-app`.** Moves `src/app/state`, `src/player` and `src/connect` out of the GTK binary. Today these import from `crate::app::models` (which wraps data in GObjects, 61 `glib::` uses) and `crate::app::components::labels` (gettext strings) and a few UI enums (`CardLayout`, `CardSize`, `SortOrder`). The extraction splits `models` into plain Rust data types (moved to `riff-app`) and GObject wrappers (stay in `src/`). Labels and UI enums move with the state or become plain enums.
2. **Event loop.** The GTK app drives dispatch from a `futures::channel::mpsc` channel on the GLib main context (`src/main.rs`). `riff-app` exposes the dispatcher and an event stream without assuming GLib. GTK keeps consuming it on the GLib main loop. The Mac app runs it on a tokio runtime and receives events through a UniFFI callback interface that hops to the Swift main actor.
3. **Platform traits.** Each GTK-only dependency gets a trait with two implementations:

    | Concern | Linux (unchanged) | macOS |
    | --- | --- | --- |
    | Image decode and cache | `gdk-pixbuf`, `gdk::Texture` in `riff-api` | Rust returns bytes, Swift decodes with ImageIO |
    | Settings | GSettings via `gio` in `riff-config` | `UserDefaults`-backed store |
    | Credentials | `oo7` (Secret Service) in `riff-auth` | Keychain via `security-framework` |
    | Audio output | librespot alsa / pulseaudio backends | librespot `rodio` backend (CoreAudio) |
    | Cache directory | `glib::user_cache_dir()` | `~/Library/Caches/com.aidenir.Riff` |
    | Media keys | MPRIS over D-Bus (`src/dbus`) | `MPNowPlayingInfoCenter` and `MPRemoteCommandCenter` (Swift) |
    | Suspend inhibit | logind (`src/inhibitor.rs`) | `IOPMAssertionCreateWithName` (Swift) |
    | Translations | gettext | String Catalog, translated in Swift |

    GTK implementations sit behind a default-on `gtk` cargo feature so the Linux build needs no flag changes.
4. **New crate `crates/riff-ffi`.** `cdylib`/`staticlib` with UniFFI. Exposes: dispatch of actions, event callback, read-only state snapshots per screen, image fetch returning bytes, login flow (loopback OAuth on `127.0.0.1:8898` works unchanged with sandbox off), feature flags.

### Swift app (`macos/`)

```
macos/
  project.yml            XcodeGen spec
  Riff/
    App/                 RiffApp, menu bar commands, Settings scene
    Core/                RiffCore wrapper: dispatch, event stream, @Observable stores
    Platform/            NowPlaying, power assertion, Keychain glue if needed
    Features/            one folder per page (Home, Library, Search, Details, Queue, Lyrics, ...)
    Components/          track row, card grid, playback bar, artwork view
    Resources/           Assets.xcassets, AppIcon, Localizable.xcstrings
  RiffTests/
  Generated/             UniFFI Swift output (gitignored)
```

State flows one way, matching the GTK design. Swift sends actions into Rust. Rust emits events. `@Observable` stores refresh from snapshots on relevant events. Views read stores only.

### Build

- `just mac` (and `scripts/build-macos.sh`):
  1. Run `scripts/generate-spotify-api.sh` if `generated/spotify-api` is missing.
  2. `cargo build -p riff-ffi --release --target aarch64-apple-darwin --no-default-features --features macos`.
  3. Generate Swift bindings with `uniffi-bindgen` and package an `.xcframework`.
  4. Convert `po/*.po` to `Localizable.xcstrings`.
  5. `xcodegen` then `xcodebuild`, producing `Riff.app`, ad-hoc signed with hardened runtime.
  6. Optional `--dmg` packs a DMG.
- Host requirements: Xcode for macOS 26 SDK, Rust stable with `aarch64-apple-darwin`, Java, XcodeGen (Homebrew).
- Linux: `meson`, `scripts/build.sh` and Flatpak are unchanged.

### CI

New workflow `riff-macos.yml` on `macos-26`:

1. `cargo test --workspace --no-default-features --features macos` for shared crates.
2. `just mac --dmg`.
3. Upload DMG as an artifact. On release tags, attach it to the GitHub release.

Notarization (`notarytool`) is added as a separate step once secrets for a Developer ID exist.

## Slices

Each slice ends with the Linux build green, the Mac app building, and the parity checklist rows for that slice ticked.

1. **Rust extraction.** Create `riff-app`, split models, add platform traits and the `gtk` feature, add `riff-ffi` with a minimal API. GTK app behaves exactly as before. No Swift yet beyond a window that prints the logged-in state.
2. **Login and playback.** Login page (OAuth in the browser), session restore from Keychain, playback bar (play/pause, next/prev, seek, volume, shuffle, repeat, artwork, track info), now-playing info and media keys, power assertion during playback.
3. **Library.** Sidebar navigation, saved albums, saved playlists (including folders), liked tracks, followed artists, artwork cache, track list with multi-select, like/unlike, follow/unfollow.
4. **Search and details.** Search with scopes, album, artist, playlist and user details pages, playlist editing (create, rename, add/remove tracks, picker), recommendations, Spotify link handling and clipboard import.
5. **Queue, lyrics, home.** Queue page and side panel, synced lyrics, home tab, now-playing page.
6. **Settings, audio engine, Connect.** Settings window with all GTK settings, equalizer, stereo pan, pitch shift, normalisation, cache controls, Spotify Connect device selector, Debug menu, feature flags, keyboard shortcuts.
7. **Release.** App icon, String Catalog conversion, DMG packaging, macOS CI workflow, README section for macOS.

## Risks

- **Model split.** `src/app/models` mixes data and GObject wrappers. This is the largest Rust change and the main risk to Linux behaviour. Mitigation: move code without changing logic, keep all existing tests passing, and run the GTK app after slice 1.
- **librespot on macOS.** The `rodio` backend and Connect zeroconf (`with-libmdns`) have not been exercised in this codebase on macOS. Slice 2 proves playback before UI work grows.
- **PlayPlay DRM.** Some accounts fail on Linux for this reason. The same applies on macOS and is out of scope.
- **Unsigned distribution.** Until notarization exists, users must clear the quarantine attribute or use right-click Open.
